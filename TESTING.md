# FinPilot × ApexBroker UI Verification Checklist

This document details the manual and automated UI verification for all 10 acceptance criteria specified in the product build spec.

### UI Test Results Summary

| # | Test Case Description | Status | Verification Notes |
|---|---|---|---|
| 1 | **3-Click Modal Reach**: Landing → Try Demo → SIPs → Pause SIP reaches modal in ≤ 3 clicks | **PASS** | Clicking "Try Demo" opens ApexBroker; clicking "SIPs" navigates to SIP tab; clicking "Pause SIP" on UTI opens FinPilot modal directly (total = 3 clicks). |
| 2 | **Reason-Based Memory Matching**: "Market worry" on UTI shows "You've been here before (12 Mar 2026)"; "Found a better option" shows no card | **PASS** | Selecting "Market worry" dynamically renders the Decision Memory card displaying past outcome (₹2,140 missed gains) and suggested action. Selecting "Found a better option" renders a clean, fresh flow with zero previous memory cards. |
| 3 | **Decision Memory Persistence & Deletion**: Deleting memory stops matching; confirming with "Remember" on adds a record that matches next time | **PASS** | Deleting a record from the manager removes it from state and localStorage. Completing a decision adds an active memory record that matches immediately on subsequent modal opens. |
| 4 | **Selected Option Reflection in Step 3 Confirm**: Confirm numbers equal the selected option's card numbers (reduce, pause, withdraw) | **PASS** | Step 3 dynamically pulls from `selectedImpact` corresponding to the chosen alternative card (Keep active, Reduce, Auto-resume pause, Use cash, or Custom), avoiding pause slider bleed. |
| 5 | **State Updates After Done**: SIP badge/amount, dashboard totals, goal card status, Activity log, 30-day check-in, toast; persistence & reset | **PASS** | State propagates to all components: SIP card reads "Paused until <date> · auto-resumes" or "Reduced to ₹X/mo for N months", dashboard totals update, check-in alert added to bell, toast displayed, and localStorage stores state. "Reset demo" reverts to initial seed. |
| 6 | **Cash vs Holding Alternative Logic**: Withdraw ₹50,000 with ₹62,000 cash shows "Use available cash instead"; ₹5,18,000 hides it; exactly one "…anyway" control | **PASS** | When `withdrawAmount <= availableCash` (₹50k <= ₹62k), the third option card offers "Use available cash instead" (₹0 goal delay). For ₹5,18,000, it is marked unavailable. Exactly one quiet "Withdraw anyway" link is rendered at the bottom. |
| 7 | **Simulated LLM Speed Controls**: Slow (1500 ms) → numbers only + fallback note; Fast → typed explanation | **PASS** | Pressing 'D' toggles the hidden demo panel. Setting speed to Slow aborts at 800ms with "Detailed explanation unavailable, showing numbers only." Setting speed to Fast types out the simulated insight in 400ms. |
| 8 | **Input Validation & Guardrails**: Invalid inputs show inline error and disable Done | **PASS** | Entering pause months outside 1–24, reduction amount >= current amount, or withdrawal amount <= 0 or > holding value renders an inline error in red and disables the Done/Proceed button. |
| 9 | **Live Non-Blocking Insight on Add Investment**: Shows "FinPilot insight" line updating with amount/type; empty input shows helper prompt | **PASS** | "Add Investment" dialog calculates live non-blocking impact (e.g., "This adds ₹X/month to Early Retirement and brings your goal about N months earlier.") while empty/zero input displays "Enter an amount to see the impact." |
| 10 | **Aesthetic & Compliance Guardrails**: No "$", "Jonathan Doe", "QQQ", "VOO", "Sips", or "from Section" in UI; no horizontal overflow at 1280 & 1440px; Esc closes modal & focus trapped | **PASS** | Verified zero forbidden strings across all source files. Indian digit grouping (₹) strictly applied. Layout responsive and verified without overflow at desktop 1280px and 1440px breakpoints. Keyboard 'Escape' closes modal cleanly. |
